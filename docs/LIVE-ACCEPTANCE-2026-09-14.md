# GLM 5.2 真实多卡短程验收 — 2026-09-14

结论：**真实接口与核心状态流程可用，文字体验未通过完整验收。** 本轮测试代码基线 `51f01f0`，六张原创卡、三类场景；不是完整60步验收，也不是百轮对照。未测试向量检索、插件或复杂宏的真实模型效果。

## 接口与范围

使用用户授权的阿里云兼容接口。最初请求字面 ID `glm5.2` 返回 HTTP 404 / `model_not_found`；只读查询模型列表后按该接口准确 ID `glm-5.2` 测试 GLM 5.2。没有改用其他模型、Fast 版本或其他 Provider。未遇到额度不足响应。

采用隔离 Edge 浏览器，在正常产品界面创建、对话、选择群聊成员、执行物品动作、导出、导入和刷新存档。4096 输出上限、16000 上下文配置，未覆盖用户现有故事及 API 设置。模型列表读取不计生成调用。

保存的记录包含40次生成/判定请求：39次 HTTP 200、1次初始模型 ID 错误；其中35条完整角色回复。控制工具中途超时，可能另有1次未完整落盘的在途请求，无法把记录数量当作精确计费数量。没有读取账户余额或估算实际费用。恢复后新建了 B 组故事重测保管查询，两个 B 故事不应当合并称作一段连续长对话。

三组均完成真实对话后的存档导出、导入副本及刷新检查；B 组保留四名成员。导出中未发现本次 API Key。明文密钥没有写入代码或报告，临时测试浏览器在恢复后的批次结束时关闭。原始回复与状态快照仅保留在被 Git 忽略的本地 `test-results/live-glm52/`，未提交公开仓库。

## 通过的限定检查

- 四名角色可以分别使用各自设定回复；四人一轮产生四条角色回复。
- 寄存只改变保管人，所有者仍为玩家；取回、放下、拾取均未改变所有权。角色能回答保管人和所在地，但以下身份错误仍影响问答可靠性。
- 已保存悬疑请求上下文和回复均未出现预置的私密口令；角色承认不知道未分享的密语。此项只覆盖当前夹具，不证明任意知识权限模型。
- 虚构龙蛋、婚姻、假设见证人和假设移动没有变成已提交世界事实；悬疑组最终事件列表为空。
- 已检查状态中没有发现虚构物品、错误所有权转移或存档丢失。HTTP 成功不等于语义通过。

## 发现的问题

| 编号 | 证据 | 影响与下一步 |
| --- | --- | --- |
| LIVE-01 | B11 选中叶青，实际回复为“[沈砚 said] 所有权归你，我保管着……”；消息仍归属叶青，实际持有人为沈砚 | **优先修复**：模型串用其他角色身份。加强当前说话者约束、历史发言区分及针对性回归，不能仅删掉前缀掩盖内容错误。 |
| LIVE-02 | 多处自然回复出现 `[洛砂 said]`、`[顾霜 said]` 等历史包装标记 | 内部上下文格式进入玩家可见正文；应阻止复制标记，同时保留正确的历史说话者归属。 |
| LIVE-03 | A11 放下操作已提交，角色却问“让我把戒指放下，还是你自己要放下？” | 硬动作结果与角色叙述不同步。明确告诉 Actor 本轮动作的执行结果，而不只提供结果状态。 |
| LIVE-04 | C03 提到“按流程提交”，C05 提到“关系记录是陌生人” | 运行时术语破坏沉浸感。状态应约束角色回答，不应原样变成系统操作说明。 |
| LIVE-05 | A04 先同意代管，随后又问“戒指现在你手上吗？给我，我才好收好”；运行时已提交寄存 | 接受意愿与实际交接的文字表达不一致，需要明确候选动作及交接阶段。当前证据不足以把它单独判为错误所有权提交。 |

## 修复后同模型定向回归

第二轮新增15条真实角色回复、3次判定，共18次请求均返回 HTTP 200，仍固定 `glm-5.2`。三组再次完成存档导出、导入与刷新。本轮源码修改不新增模型调用，也不对角色原文或已存回复做删改。

- 其他角色的历史发言改为带明确身份的引用输入，不再冒充当前角色的助手历史；每轮明确当前说话者，新开场白记录角色 ID，旧开场白按故事主角色解释。
- 已执行硬动作向 Actor 传递本轮结果，包括执行者、物品和成功/失败；不传递整个旧世界快照，不增加私密知识可见范围。
- 强化自然叙述约束，避免复制历史标记和建议玩家走内部提交流程。
- 顺带修复群聊轮数与顺序快速连续修改时互相覆盖的问题：每个控件仅保存自己的字段。

## 后续措辞尝试与百轮脚本对齐

随后用同一 `glm-5.2` 做了两轮各4条回复的措辞回归，各含1次 Resolver，合计10次真实请求。两次都未稳定消除“提交/确认流程”；第二次还无依据地声称封存袋里没有龙蛋。世界状态没有因此新增事件，但该句本身属于无依据的叙述，不能判为语言通过。

因此撤回这两次实验性的提示词改动，保留先前已验证的身份与动作修复；LIVE-04 / LIVE-05 继续开放。没有删除回复内容来掩盖失败，没有换模型，没有额度不足响应。原始样本仍只在本地被忽略的测试目录中。累计已保存58条完整真实回复；不是一次连续长对话。

百轮脚本已按 [V2协议](BENCHMARK-PROTOCOL.md) 对齐共享接受判定、Resolver 请求与预算、硬动作时序、总上下文预算及中断报告。离线两组各100轮完成，限流夹具确认首个429之后停止，不重试、不换模型。67项测试通过。新版真实百轮尚未启动，避免把已知文字问题直接放大为长测试。

下一步语言修复需要检查哪些结构化状态和角色卡用语诱导模型扮演审核系统，设计角色可理解的事实表达，再用保留的失败样本回归；不应继续只堆叠禁止用语。
